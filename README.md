# CampusConnect AI

Connect Beyond Campuses. Collaborate Without Limits.

CampusConnect AI is a student networking and collaboration platform. It includes a React/Vite client and an Express, MongoDB, and Socket.IO API. Team recommendations use an explainable skill-overlap score; they are not generated by a trained machine-learning model.

## Requirements

- Node.js 20.19+ (Vite 8 requirement)
- npm
- MongoDB Atlas or another MongoDB instance

## Run locally

1. In `server`, copy `.env.example` to `.env` and set `MONGO_URI` and a long, random `JWT_SECRET`. Do not commit `.env`.
2. Install and start the API:

   ```powershell
   cd server
   npm install
   npm run dev
   ```

3. In a second terminal, install and start the client:

   ```powershell
   cd client
   npm install
   npm run dev
   ```

4. Open `http://localhost:5173`. Vite proxies `/api` and Socket.IO to the local backend. Set `VITE_API_URL` in `client/.env` only if you use a different API origin.

## Deploy frontend and backend together on Render

The root `render.yaml` configures one Render Web Service: it builds the React app and serves the built files and Express/Socket.IO API from the same origin.

1. Push this project to a GitHub repository. Ensure `server/.env` is not committed.
2. In Render, choose **New → Blueprint**, connect the repository, and apply `render.yaml`.
3. In the service's Environment settings, set `MONGO_URI` to your MongoDB connection string. Render generates `JWT_SECRET` from the Blueprint; keep it private.
4. In MongoDB Atlas, allow network access from your Render service. For production, restrict this to Render's outbound IPs where your plan supports static outbound IPs; avoid a broad public allowlist when possible.
5. Wait for the deploy and open the Render service URL. Check `/api/health`; it should return `"database":"Connected"`.
6. Create an admin account through a controlled database provisioning step if moderation access is needed.

The free Render service can sleep when idle, and its filesystem is ephemeral: uploaded profile photos may disappear on restart/redeploy. Use a paid persistent disk mounted at `server/uploads`, or move uploads to durable object storage, before relying on photo uploads in production.

## Architecture

- `client/src/App.jsx`: public landing/auth pages, protected app shell, and API-connected student/admin screens.
- `server/server.js`: Express API, CORS, Socket.IO authentication and conversation rooms.
- `server/routes/`: route-level authentication and role checks.
- `server/controllers/`: request handling and feature logic.
- `server/models/`: Mongoose schemas and MongoDB references.
- `server/config/db.js`: MongoDB connection and the existing Atlas DNS resolver workaround.

The API is grouped under `/api`: `auth`, `users`, `posts`, `projects`, `applications`, `skills`, `help`, `messages`, `notifications`, `ai`, and `admin`. Private routes use JWT bearer tokens; admin routes additionally require the admin role.

## Available workflows

- Student registration/login, profile editing, student search, and profile-photo uploads (JPEG/PNG/WebP, 2 MB maximum)
- Community posts, edit/delete, likes, comments, and reports
- Projects, detail pages, applications, owner application review, and reports
- Skill offers/learning requests
- Questions, answers, accepted answers, and reports
- Direct conversations, message history, and authenticated Socket.IO events
- Readable/deletable notifications
- Skill-overlap teammate recommendations
- Reports for users, posts, comments, projects, skill listings, and help questions; admin statistics, report review, and student account activation/deactivation

## Configuration

See `server/.env.example` and `client/.env.example`. The backend retains the configured DNS resolver workaround for MongoDB Atlas SRV lookup. In the single-origin Render setup, no separate client CORS origin is required. If deploying the frontend separately, set the server's `CLIENT_URL` to that exact origin and build the frontend with its `VITE_API_URL`.

## Quality checks

Run from `client`:

```powershell
npm run build
npm run lint
```

Run the API from `server` with `npm start`; `GET /api/health` is the basic availability check. The app also needs a reachable MongoDB instance and valid environment values for authenticated/database-backed workflows. There is no automated integration-test suite in this workspace.

## Manual testing checklist

- Register a student with skills and interests; log in and log out.
- Edit profile details and search for another student.
- Publish a post, like it, add a comment, and delete your own post.
- Create a project, apply from another account, and accept/reject as its owner.
- Create and filter skill offers and learning requests.
- Ask a question, answer it as another account, and accept an answer as its author.
- Start a direct conversation; verify message history and live updates with both clients open.
- Mark notifications read and delete a notification.
- Run team matching for a project with required skills and check the returned skill overlap.
- Verify a student cannot access admin APIs and an admin can view statistics/review reports.

## Deployment notes and current API limits

- Create the initial admin account through a controlled database/admin provisioning process; public registration creates student accounts only.
- Profile-photo files are stored on the server disk in `server/uploads`; use persistent storage or object storage when deploying.
- Use HTTPS, a production-specific `CLIENT_URL`, a strong JWT secret, and managed MongoDB credentials in production.
